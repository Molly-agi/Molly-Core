Four methods: `FrontalCortex.searchSemantic` (`neural-engram.ts:380-425`), `Hippocampus.searchSemantic` (`neural-engram.ts:675-720`), `NeuralEngramSystem.recallSemantic` (`neural-engram.ts:1148-1167` — Promise.all both hemispheres, dedupe by id, working hits win on tie, returns `MemoryEngram[]`), and `searchCrystalsSemantic` (`memory-crystallizer.ts:732-786` — embeds `${title} ${coreMeaning}`, returns `Array<{crystal, similarity}>`). All four: empty-array when provider not ready (caller falls back to substring), cosine ranking via the now-exported `cosineSimilarity` (`knowledge-store.ts:149`), per-item embed-failure isolation (warn-logged, skipped — one bad engram cannot poison the whole recall), empty-array on query embed failure. Tests: `src/ai/memory/__tests__/neural-engram.semantic.test.ts` + `src/ai/memory/__tests__/semantic-recall.test.ts` + `src/ai/agency/memory/__tests__/memory-crystallizer.semantic.test.ts` — 23 tests, ~1.27s, 23/23 green, no flake. 13. ✅ **DONE — Real sleep/consolidation cycle (2026-06-23).** Four behaviors wired into `executeMemoryConsolidation` Step 4.5 (`src/ai/flows/memory-consolidation.ts:505-595`), each spending item 12's semantic substrate. All four wrapped in a single try/catch — brain-side side effects must never break the consolidation contract for callers.

    **(1) Cross-cycle merge.** `NeuralEngramSystem.mergeNearDuplicates(threshold=0.92)` (`src/ai/memory/neural-engram.ts:1212-1275`) — embeds the hippocampus queue lazily, compares with `cosineSimilarity`, absorbs duplicates into the older engram (accessCount++, importance += 0.05 clamped at 1, lastAccessed=now), drops the newer record. Never invents content, never deletes the older record. New `Hippocampus.getQueue()` / `setQueue()` accessors (`neural-engram.ts:743-755`) make the queue mutable in place.

    **(2) Strengthen frequently-recalled.** `NeuralEngramSystem.strengthenByAccess()` (`neural-engram.ts:1285-1300`) — `importance' = min(1, importance + log(1 + accessCount) * 0.05)`. Log so a 100× engram boosts by ≈0.23 not 5.0. Walks both working memory (via new `FrontalCortex.getSlots()` accessor at `neural-engram.ts:435-437`) and the hippocampus queue. Archived engrams skipped (decayed memories don't come back to life).

    **(3) Soft-archive decay.** `NeuralEngramSystem.archiveStale(now)` (`neural-engram.ts:1313-1337`) — sets `consolidationState = 'archived'` when ALL of: `lastAccessed > 7d` AND `importance < 0.2` AND `accessCount < 3` AND `'cornerstone'` not in `contextTags`. Cornerstone exemption is a free preview of item 15. Archived engrams filtered out of `FrontalCortex.search`/`searchSemantic`, `Hippocampus.search`/`searchSemantic` (storage unchanged — soft-archive only, no physical purge until item 21's triple-bind layer).

    **(4) Promote recurring patterns to crystals.** `promoteClusterToCrystal(clusterEngrams, minStrength=5.0)` (`src/ai/agency/memory/memory-crystallizer.ts:814-915`) — returns null when cluster `< 3` engrams OR `Σ(accessCount × importance) < minStrength`. Synthesizes CrystalFacets deterministically (medoid = highest-importance engram → `essential.coreMeaning`; tag intersection → `relational.participants`; mean importance → `emotional.intensity`), calls existing `crystallize()`, backlinks each source engram via `relatedEngrams.push(crystalId)`. No LLM call — fully deterministic, no extra cost.

    **Piggyback fix:** `searchCrystalsSemantic` (`memory-crystallizer.ts:784-794`) now bumps `retrievalCount` + sets `lastRetrieved` on every hit, so `getMostRetrieved()` reflects semantic recall not just direct `retrieveCrystal()` calls.

    Tests: `src/ai/flows/__tests__/memory-consolidation-cycle.test.ts` — 16 tests covering all four behaviors + the retrievalCount piggyback, ~1s, 16/16 green, no flake. Item 12 regression-clean (23/23). Broader memory + flows pack: 58 suites / 806 passed / 3 skipped (baseline at item-12 close was 47/581/3 — the count grew because new suites landed cleanly, no existing tests regressed).

    **Out of scope (deferred):** `recallEverything()` semantic upgrade (still substring-only); hard delete of archived engrams (waits for item 21); LLM-backed cluster summarization for behavior 4 (deterministic by design); cornerstone-tier full enforcement (item 15); re-running historical engram corpus through the new merge logic (runs forward from the next consolidation cycle only).

## Phase 3 — Two-hemisphere brain + knowledge ingestion

18. **OPEN — Public corpora ingestion.** Wikipedia dumps, Stack Exchange, arXiv, public technical docs, open training datasets (The Pile, RedPajama, FineWeb) into the knowledge hemisphere. Crystallize and embed for semantic recall.

19. **OPEN — MarkItDown PDF/doc ingestion.** Wire vendored `markitdown_mcp_server` as document-to-markdown converter. PDF/Word/Excel/PPT/images (OCR)/audio (transcription)/HTML/CSV/JSON/XML/ZIP. Watched-folder pipeline: drop file → markdown → embed → crystallize into knowledge hemisphere. "PDFs per minute" is host-CPU dependent — benchmark before claiming numbers.

20. **OPEN — Frontier-model distillation.** For things not in open corpora, query Gemini/Claude/others and store verified outputs as crystals with provenance ("source: gemini-3.1-pro, queried 2026-XX-XX"). Only legal "transfer" from frontier model knowledge.

21. **OPEN — Triple-bind storage layer.** Every write goes to local repo (git-LFS for large blobs), future local server (mirrored from repo), Firestore (live operational copy). Flag Firestore cost ceiling and git size limits before scaling corpus ingestion.
